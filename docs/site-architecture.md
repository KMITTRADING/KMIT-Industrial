# Site architecture

> Written in Phase 1 using the `site-architecture` skill, against
> `.agents/product-marketing.md` and `docs/keyword-clusters.md`.
> Routes marked **Phase 3** are built in Phase 3; **Phase 7** routes are the
> programmatic growth layer and are not built before launch.

---

## 1. The two paths

The IA follows directly from the two personas in `.agents/product-marketing.md`
§3, who arrive with different questions and must not be funnelled through the
same page:

- **The engineer** arrives on a grade or an application page, usually from a
  specification query. They need numbers, then a sample.
- **The procurement manager** arrives on the home page or a supplier query. They
  need packaging, geography and documentation, then a quote.

Every page therefore belongs to one of two lanes — _specification_ or _supply_ —
and every page offers a bridge to the other lane exactly once.

## 3. Hierarchy

```
Home (/[locale])
├── Products (/products)                      grade matrix, all five grades
│   ├── GCC-200   (/products/gcc-200)
│   ├── GCC-400   (/products/gcc-400)
│   ├── GCC-800   (/products/gcc-800)
│   ├── GCC-1250  (/products/gcc-1250)
│   └── GCC-2500  (/products/gcc-2500)
├── Applications (/applications)              sector index
│   ├── Plastics & masterbatch      (/applications/plastics)
│   ├── Paints, coatings & construction (/applications/paints-construction)
│   ├── Drilling fluids             (/applications/oil-gas)
│   ├── Rubber & elastomers         (/applications/rubber)
│   └── Paper & paperboard          (/applications/paper)
├── Quality & compliance (/quality)           standards, test methods, COA
├── Facility (/facility)                      extraction → milling → QC → despatch
├── Technical documents (/resources)          TDS / MSDS / COA library
├── Contact (/contact)
└── Request a quote (/rfq)                    conversion endpoint
```

Maximum depth is three clicks from the home page to any grade page. Nothing on
this site needs a fourth level, and adding one would bury the grade pages, which
are the highest-intent documents on the site.

## 4. Navigation model

**Primary nav — five items.** `Products · Applications · Quality · Resources ·
Contact`, plus a visually distinct `Request a quote` action and the locale
switcher. Five is the cap from CLAUDE.md; Facility lives inside Quality's
mega-menu column rather than taking a slot of its own.

**Products mega-menu.** The highest-intent path, so it exposes the grade matrix
directly rather than a list of links: grade code, mesh, D50 and coated/uncoated
in a compact table, each row a link. A procurement manager who knows they need
1250 mesh reaches the page in one click from anywhere on the site.

**Applications menu.** Five sector links with a one-line technical-value
summary each, drawn from `docs/technical-data.md` §4.

**Mobile.** A full-height panel, sections collapsed to headings. The grade
matrix becomes a scrollable list of rows — never a nested accordion three levels
deep.

**Footer.** Full sitemap in four columns, the compliance line, and the data
provenance statement. The footer is where the long tail of links lives so the
header can stay at five items.

**In the header at all times:** the locale switcher, and — once contact details
exist — a WhatsApp affordance. WhatsApp is a primary B2B channel in the GCC and
belongs in the header, not buried in the footer.

## 5. Internal linking map

Anchor text is the same in both locales in _meaning_, and always names the
target: a grade code, a sector, or a document type. Never "click here", never
"learn more".

| From                     | To                        | Anchor text pattern              | Why                                  |
| ------------------------ | ------------------------- | -------------------------------- | ------------------------------------ |
| Home                     | `/products`               | grade matrix rows (`GCC-1250`)   | Highest-intent path, direct          |
| Home                     | `/applications/[sector]`  | sector name                      | Second entry lane                    |
| Home                     | `/rfq`                    | "Request a quote"                | Conversion                           |
| `/products`              | `/products/[grade]`       | grade code                       | One row per grade                    |
| `/products/[grade]`      | `/applications/[sector]`  | sector name                      | Spec → application bridge            |
| `/products/[grade]`      | `/products/[related]`     | related grade code               | Adjacent grades from `relatedGrades` |
| `/products/[grade]`      | `/rfq?grade=CODE`         | "Request a quote for GCC-1250"   | Prefilled conversion                 |
| `/products/[grade]`      | `/quality`                | test method name                 | Backs the numbers                    |
| `/products/[grade]`      | `/resources`              | "Technical data sheet"           | Documentation                        |
| `/applications/[sector]` | `/products/[grade]`       | grade code                       | Application → spec bridge            |
| `/applications/[sector]` | `/rfq?application=SECTOR` | "Request a quote for {sector}"   | Prefilled conversion                 |
| `/quality`               | `/resources`              | "Certificate of Analysis"        | Document path                        |
| `/quality`               | `/facility`               | "processing and quality control" | Capability proof                     |
| `/resources`             | `/rfq`                    | "Request the document"           | Capture                              |
| `/facility`              | `/products`               | "the grade range"                | Back to spec                         |
| Every page               | `/rfq`                    | primary action in header         | Always reachable                     |

**The rule that matters:** every grade page links to its sectors, and every
sector page links back to its grades. The grade × sector relationship is already
modelled in `APPLICATION_SECTOR` in `src/content/schema.ts`, so this linking is
generated from the data, not hand-maintained — which is the only way it stays
correct across two locales and ten pages.

**Cross-locale linking:** never. `/ar` links only to `/ar`. The only path
between locales is the locale switcher, which stays on the same document. This
is enforced by importing `Link` from `@/i18n/navigation` rather than
`next/link`.

## 6. Breadcrumbs

Rendered on every page below L0, as an ordered list, and mirrored into
`BreadcrumbList` JSON-LD in Phase 5.

```
Home / Products / GCC-1250
Home / Applications / Plastics & masterbatch
Home / Technical documents
```

The separator is a CSS pseudo-element rather than a character in the markup, so
it flips automatically in RTL and is not read aloud by a screen reader. The
current page is the last item, marked `aria-current="page"` and not linked.

## 7. Conversion paths

Three, each prefilling the RFQ so the buyer is never asked for something the
page already knows.

1. **Grade page → RFQ prefilled with grade.**
   `/[locale]/products/gcc-1250` → `/[locale]/rfq?grade=GCC-1250`.
   The form opens with the grade locked and visible, and asks for tonnage,
   packaging and destination. Highest-intent path on the site.

2. **Application page → RFQ prefilled with sector.**
   `/[locale]/applications/plastics` → `/[locale]/rfq?application=plastics`.
   The form opens with the sector set and _suggests_ the grades that serve it,
   from the dataset — the buyer confirms rather than specifies.

3. **Resources → document request → capture.**
   `/[locale]/resources` → request a TDS/MSDS/COA → the same RFQ adapter with a
   document-request intent. Deliberately not a gated download: the specification
   is already published on the grade page, so gating the PDF of numbers the
   visitor can already read would be theatre. What is captured is the _request
   for a controlled document_, which is a real qualification signal.

All three land in `submitRfq()` in `src/lib/rfq-adapter.ts`. The query
parameters are validated against `GRADES` and `APPLICATION_IDS` — an unknown
value is dropped, not rendered, so the URL cannot be used to inject text into
the form.

## 8. What this architecture deliberately does not have

- **A blog.** Cluster 4 becomes `/knowledge` in Phase 7 — a reference section,
  not a dated feed. Dated posts age visibly and a two-year-old post reads as an
  abandoned company.
- **A pricing page.** Price is a function of grade, volume, packaging and
  destination. A page that says "contact us for pricing" is a dead end; the RFQ
  _is_ the pricing path.
- **A news or events section.** No content to put in it, and an empty one is
  worse than none.
- **A team page.** No photography, and a stock-feeling team page reduces trust
  with this audience. See `docs/asset-map.json` → `gaps`.
- **Locale-specific URL structures.** Both locales have identical trees. Any
  divergence would break the hreflang cluster.
